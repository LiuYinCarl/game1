# 玩法逻辑 bug 记录

## 士兵出生坐标被缩放动画放大，飞出地图

**现象**：兵营造好后，士兵有时出现在 y ≈ -800000 的地方（直接飞出屏幕外），集合点空无一兵。

**原因**：士兵是兵营的**子节点**，而兵营建造时有 0 → 1 的缩放弹出动画。在缩放接近 0 的那一帧给士兵赋 `global_position`，Godot 换算局部坐标时要**除以父级缩放**，(0, -8) 除以近零值就变成了天文数字，之后父级缩放恢复也回不来了。

**修复**：子节点的出生位置直接用局部坐标 `s.position = Vector2(0, -8)`，不要在父节点有缩放动画时写 `global_position`。

**通用教训**：给挂在"有缩放/位移动画"的父节点下的子节点设置位置时，优先用局部坐标；`global_position` 的读写都隐含父子变换换算，动画期间不安全。

## 建造/升级菜单不随金币刷新

**现象**：菜单打开时金币不够，按钮是灰的；边打怪攒够了钱，按钮依然灰着，要关掉菜单重开才能点。

**原因**：按钮的 `disabled` 只在菜单创建时算了一次，之后金币变化没有任何回调去刷新它。

**修复**：创建按钮时把 `[按钮, 所需金币]` 登记到 `menu_buttons` 数组，`_update_hud()`（金币一变就触发）里统一刷新 `disabled = gold < cost`。

**教训**：任何"打开时根据状态计算 UI 可用性"的面板，只要背后状态会持续变化，就需要一个刷新通路；否则就是这类"面板开着但状态过期"的 bug。

## 冒烟测试污染真实存档

**现象**：跑了几次无头冒烟测试（`--smoke`）后，开始界面里 6 关全部解锁且全是 3 星。

**原因**：冒烟测试用的是真实游戏流程，通关同样触发 `GameState.complete_level()` → 写 `user://save.json`，把真实进度覆盖了。

**修复**：`game_over()` 里冒烟模式跳过存档写入。**任何会写持久化数据的自动化测试，都要有"不落盘"的开关**，最好默认不写。

## 敌人被路径逻辑"拉回"出生点

**现象**：想在截图模式里把一个敌人钉在指定位置，直接设 `position` 无效——下一帧它就被传回路径起点。

**原因**：敌人的 `position` 每帧由 `seg` / `seg_progress`（路径进度）推算出来，直接改 position 会被覆盖。

**修复**：设置 `seg` 和 `seg_progress` 到目标位置对应的路径段（用 `Geometry2D.get_closest_point_to_segment` 求最近段），position 只是推算结果不是状态源。

**教训**：位置由插值/进度推算的实体，要移动它得改"驱动状态"（进度参数），不能改表现值。
